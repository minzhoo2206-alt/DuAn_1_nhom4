2. Extract this ZIP into project root. In phpMyAdmin, as local root, select `fourtech_admin_test`, import `docs/admin-test-rbac.sql`, then `docs/admin-test-rbac-bootstrap.sql` once. Bootstrap promotes the named active staff account only when no active admin role assignment exists. Its final SELECT must show `admin17@example.test` / `task17_admin`. If not, stop and inspect existing roles/accounts. Do not run on hosting. No new privileges for existing app user beyond SELECT/INSERT/UPDATE in test schema.
3. `php docs/check-admin-rbac-rules.php`, then `php -S 127.0.0.1:8001 -t public docs/admin-db-test.php`. Open `/admin/login`, sign in with the admin email and password created at step 1. `/admin/rbac` shows matrix, role assignment, grant/revoke staff catalog write. To test another account simultaneously use a separate private browser session. Staff defaults to read only; customer has no admin access. Try direct URLs and POST with missing CSRF. Revoke permission and refresh staff page; permissions queried every request. A locked user or changed password invalidates their local session on next request. Customer role is reversible in RBAC screen; Task 16 account edit only supports staff. Admin cannot be changed via UI; bootstrap is a local DBA-only operation. Staff may see old catalog action buttons but server denies unauthorized requests.
4. Inspect SQL (read-only): `SELECT u.email,r.code FROM users u JOIN user_has_roles ur ON ur.user_id=u.id JOIN roles r ON r.id=ur.role_id WHERE u.deleted_at IS NULL AND ur.deleted_at IS NULL AND r.deleted_at IS NULL;` and `SELECT r.code AS role_code,p.code AS permission_code FROM role_has_permissions rp JOIN roles r ON r.id=rp.role_id JOIN permissions p ON p.id=rp.permission_id WHERE rp.deleted_at IS NULL AND r.deleted_at IS NULL AND p.deleted_at IS NULL;`.

Scope: existing ERD tables roles, permissions, user_has_roles, role_has_permissions; local DDL and role/permission codes are test choices, not agreed production migrations. Local login restricted to @example.test, loopback router, one active role per account, 1h session, CSRF on writes/logout/login, permission checks server-side for recognized routes; session-local attempt limit only, not production rate limiting. Admin role and permission catalog fixed; can change staff/customer assignments and staff catalog write grant only. No general role CRUD, arbitrary permission editor, customer storefront login, official auth, 2FA, real audit actor IDs, or full production concurrency/TOCTOU guarantees. Permission changes apply to subsequent requests, not already executing requests. Core of Minh not modified. Production requires agreed role codes and permissions, official middleware, authenticated actor, audit, session revocation, encrypted PII, verified accounts, persistent rate limiting, 2FA, shared lock ordering and real integration tests with Nhuận and Minh. Do not deploy docs router to hosting.
